     与 Folia `Median Region TPS: 18.96` / `Lowest Region TPS: ...`

3. **CPU 采样需按 PID 重置基线**：实例重启后进程 CPU 计数器回退，

运行：`bash scripts/test.sh`（含 `go vet`）。

> **测试立刻发现一个真实缺陷**：`POST /api/users` 误挂 `requireAuth`，
> 导致全新部署**无法创建首个管理员**（中间件先返回 401，`handleRegister`
> 中「首个用户自动成为 admin」的逻辑永远走不到）。已改为 `optionalAuth`。

**③ 安全加固**
- **JWT 密钥**：未配置/占位符 → 自动生成 32 字节随机密钥持久化到 `data/jwt.secret`(0600)；
  显式配置但短于 32 字符 → **拒绝启动**
- **登录限流**：双维度（用户名 5 次/15 分钟 → 锁 15 分钟；IP 50 次/10 分钟 → 锁 5 分钟）。
  IP 阈值远高于用户名维度，避免面板位于 frp/反代之后时**单个攻击者锁死所有用户**
- **`trust_proxy`**：位于代理后时取 `X-Forwarded-For`（否则审计与限流全记作代理地址）
- **控制台日志轮转**：`console.log` 超 64MB 滚动、保留 3 份
  （必须在进程启动前执行 —— Minecraft 持有 stdout fd，运行中轮转会导致写入错误文件）

### 第 2 批：生产必需（✅ 已完成）

**④ Panel ↔ Daemon 双向 mTLS**
- 面板内置 CA（首次启动自动生成），管理员可为节点签发独立证书
- **两个方向都校验**：节点须持 CA 签发证书才能接入面板；面板调用节点时也出示客户端证书
- 证书含 **SAN**（`atlmcpanel-panel` / 节点名）—— Go 1.15+ 拒绝仅 CN 的证书
  （该问题曾在线上导致 Daemon 无法接入，已加回归测试）
- API：`GET /api/pki`、`GET /api/nodes/{id}/cert`、`POST /api/nodes/cert`
- 详见 `docs/MTLS.md`

**⑤ 面板数据库自动备份**
- 使用 `VACUUM INTO` 生成**一致性快照**（WAL 模式下直接复制文件可能损坏）
- 启动时按间隔自动补备份 + 定时轮询；默认保留 7 份；支持手动触发
- API：`GET/POST /api/panel-backups`

**⑥ 状态以 Daemon 上报为准**
- 列表接口并发向各节点查询实际状态（3 秒超时、最多 8 并发），返回 `live_status`
- **自愈**：与数据库不符时回写 —— 进程崩溃/OOM 被杀后不再误报「运行中」
- 启停操作后向 Daemon 确认实际状态，而非凭动作推断

## M7 — 安全加固与启动脚本（✅ 已完成）

### ① 文件管理中隐藏 frp 内部信息（安全修复）

**问题**：实例目录下的 `frpc.toml` / `tunnels.json` 含有 frps 的 **auth token**。
该 token 是**平台级共享密钥** —— 任何具备 `collab`（只读即可）权限的实例协作者
都能读到，进而用它在 frps 上自行创建隧道。这是真实的越权风险。

**处理**：
- 受保护文件：`frpc.toml`、`tunnels.json`、`frpc.pid`、`logs/frpc.log`
- 文件列表**不显示**，读取/写入/删除**一律拒绝**（统一提示"由面板统一管理"）
- 普通日志（`console.log`、`latest.log`）与其它文件不受影响
- 穿透状态与错误仍可在管理员专属的「穿透管理」中查看

**不牺牲可排查性**：由于 frpc 日志不再开放，进程异常退出时改为
**从日志中提取关键错误行**写入隧道状态（`live_error`），管理员在穿透管理页
即可看到失败原因。

### ② 服务器启动脚本可视、可改

**新增启动方式优先级**（高 → 低）：

1. **实例目录下的 `start.sh`** —— 存在即执行，可写任意启动逻辑
2. **自定义启动命令**（`instance.json` 的 `start_command`，支持占位符）
3. **默认 java 命令** —— `java -Xms… -Xmx… -jar 核心.jar nogui`

**面板「启动」页签**提供：
- 当前生效方式与实际会执行的命令预览
- 一键**从当前配置生成** `start.sh`（展开绝对路径、先 `cd` 到脚本目录、用 `exec` 让 java 接管进程）
- 内置编辑器直接修改保存；也可在文件管理中编辑（通过 `sh` 调用，**无需 chmod +x**）
- 删除脚本即恢复为面板配置的启动命令

> **顺带修复的真实 bug**：`registry.Load()` 未恢复 `StartCommand`，
> 导致自定义启动命令在 **Daemon 重启后丢失**、静默退回默认 java 命令。
> （`Create()` 有设置，`Load()` 漏了。）

**验收**（已验证）：
- frp 四个文件在列表中不可见；直接读取/写入/删除均被拒绝；隧道功能不受影响
- 生成脚本 → Daemon 日志 `start_mode: "start.sh"`；`daemon.pid` 记录的是 java 进程 PID
  （证明 `exec` 生效，停止/接管正常）
- 修改脚本后重启：自定义 `echo` 出现在控制台、自定义 JVM 参数出现在进程命令行
- 删除脚本后重启：`start_mode: "default"`，实例正常运行
