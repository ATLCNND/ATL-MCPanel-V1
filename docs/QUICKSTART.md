# 快速上手

> ## ⚠️ 版本提示（2026-10-25）
>
> **请使用 `0.11.0`。** 它与后续版本的能力差别不在「面板功能」，而在**实例类型**：
>
> | 版本 | 状态 |
> |---|---|
> | **0.11.0** | **推荐**。标准用法下只有 **Minecraft** 实例；其它服务可用「完整文件 + `start.sh`」直接启动（非标准用法）。凭证交换（面板发起）、面板 HTTPS、安全入口均可用。 |
> | 0.12.x | **已撤回**，不建议使用。该系列尝试用「同一套实例模型 + 模板兼容」的方式支持 Docker/通用控制台，经实测判定这条路线需要**重写**（三种实例类型应各有后端与能力）。 |
>
> 撤回的详细原因与后续计划见仓库内 `docs/V1.0-PREVIEW-GOALS.md` 的 §11（修订 -offset_correction）。

从零到「面板能打开、节点已接入、实例跑起来」，大约 10 分钟。

> 完整的参数说明见 [DEPLOYMENT.md](DEPLOYMENT.md)，架构见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 1. 准备

| 需要 | 说明 |
|---|---|
| 一台管理机 | 跑**面板**（Panel），建议 1 核 1G 起步 |
| 一到多台游戏机 | 跑**节点守护进程**（Daemon）与服务器实例 |
| Linux | x86_64 或 arm64，Systemd，建议 Debian 12/13 或 Ubuntu 22.04+ |
| Java | 节点上需要 JDK 21（跑 Minecraft 服务端） |
| Docker（可选） | 想用**容器化实例**才需要 |

面板与节点可以是同一台机器。

## 2. 安装面板

从 [Releases](https://github.com/ATLCNND/ATL-MCPanel-V1/releases) 下载与架构匹配的 `panel` 包：

```bash
tar xzf atl-mcpanel-*-linux-amd64-panel.tar.gz
cd atl-mcpanel-*-linux-amd64-panel
sudo bash deploy/install.sh panel
```

安装脚本会创建 `/opt/mcpanel`、装好 Systemd 服务并启动。

**首次登录后立刻做两件事**：

1. **立刻改掉默认管理员口令**（初始口令写在安装输出里，登录后请第一时间更换）
2. 给面板配上 HTTPS 证书 —— 否则浏览器会限制剪贴板等能力（复制按钮会退化成兼容模式）

## 3. 接入节点

1. 面板 →「节点管理」→「登记节点」，填**面板连它的地址**（`ip`）与**玩家连它的地址**（`public_ip`）
2. 填 SSH 用户/口令或私钥 → 点「部署」，面板会把 Daemon 推上去并装成服务
3. 节点状态变成「在线」即接入成功

> `public_ip` 只有做**公网直出**才用得上；不填不影响其它功能。

## 4. 建一个实例

「实例管理」→「新建实例」→ 选核心（Paper / Fabric / Forge 等）、版本、内存 → 创建 → 启动。

首次启动会下载服务端 jar，视网络情况需要几分钟。日志里出现 `Done (…)` 即为启动完成。

## 5. 让人连进来（三种方式）

选一种即可，都支持随时切换：

| 方式 | 适合 | 要点 |
|---|---|---|
| **自建 frps** | 有自己的公网服务器 | 面板里加一条线路，填 frps 地址与端口段；面板从端口段里给每条隧道分配端口 |
| **第三方单隧道** | 想让服务商代管穿透 | 复制服务商给的 `frpc` 配置 → 面板「穿透管理」→「导入配置」，解析后自动建线路与隧道 |
| **公网直出** | 节点本身有公网 IP | 加一条「公网直出」线路，地址填该节点的 `public_ip`；不需要 frp |

导入第三方配置时，服务商要求的 token 位置（`auth.token` 还是 `metadatas.token`）、代理名、带宽参数都会被原样保留 —— 这些细节填错服务端就会拒绝，所以**不要手改**。

## 6. 确认能连通

在「穿透管理」里对那条线路点「自检」：

- 自建 / 第三方：会真的用 frpc 登录并注册一次（随后撤销）
- 公网直出：会校验线路地址是否等于节点公网 IP，并从节点实拨该端口

两条都通过，玩家就能连了。
