# 0.9.15 新功能与修复

> 面向**使用者**的说明。实现细节与排查记录在仓库的开发文档里，这里只讲"你会看到什么变化"。

---

## 1. 求助文本有了模板，而且管理员可以改

日志分析走 **mclo.gs**（不做 AI、只把日志变成可分享链接的那条保底通道）时，
面板会替你拼好一段**可以直接粘到社区**的求助帖：日志链接、服务端核心与 Java 版本、
内存上限、运行方式、你自己填的现象。

**0.9.15 起这段文本由「求助模板」决定：**

- 面板**预置了一套可用的默认模板**，装好就有效，不需要配置；
- 总管理员可以在「**分析平台**」页里改措辞，点占位符徽标即可插入变量；
- 可用占位符：`{instance}` `{panel}` `{url}` `{raw_url}` `{errors}` `{core}`
  `{java}` `{mem}` `{runtime}` `{phenomenon}`；
- **某一行上的占位符全部为空时，整行会消失** —— 不会留下 `· Java：` 这种悬空标签；
- `{url}` 是唯一必填的占位符（没有日志链接的求助帖没有意义），保存时会校验；
- 把模板清空 = 恢复内置默认。

**上传之前就能看到成品**：确认弹窗里会显示渲染后的求助文本，改「现象」实时跟着变。
（这一步是必需的：模板可改之后，只显示一堆 `{占位符}` 你根本不知道自己最后会贴出去什么。）

## 2. mclo.gs 的同意流程不再卡住

以前「同意并分析」按钮的禁用条件有**三个**，而界面上只看得见一个：
除了弹窗里的勾选框，还有一个"已读使用须知"的标记存在浏览器里，
两个都满足按钮才亮，而且界面**不说明为什么不能点**。于是最常见的走法会卡死：
点开须知链接 → 勾上"我已阅读" → 关闭 → 回来按钮还是灰的。

现在：

- 选中 mclo.gs 点「一键分析」时，**使用须知会自动弹出来**；
- 须知底部只有一个「**我已阅读并理解**」按钮 —— 点它即记下已确认，
  并顺带勾上弹窗里的上传确认（那个勾选框仍然保留、仍然可以取消，只是不用点第二次）；
- 按钮置灰时，**旁边会直接写明原因**。

## 3. 已有实例可以换 JDK 了

以前 `Java 版本` 只在**建实例时**能选，建完就改不了（要换只能删掉重建）。

现在在实例页的「**启动**」页签里有一块「**Java 版本（JDK）**」：

- 下拉选项来自 Daemon 对**该节点上实际安装的 JDK** 的探测，另有「自动（用 PATH 上的 java）」；
- 保存后**重启实例生效**（运行中的实例不受影响，它启动时就把解释器定死了）；
- 换成不存在的版本不会让实例起不来 —— 启动时会回退到 PATH 上的 `java`，
  并把回退原因显示在实例页上。

## 4. 公网地址自动带上端口

管理员在「穿透管理」里**只需要填域名**，端口由面板按这条隧道实际用的端口自动拼。
以前只填域名时会显示成 `mc.example.com`（连不上的地址），现在会显示 `mc.example.com:25575`。

> 如果你在隧道上**自己写了端口**（例如外面还挡了一层 NAT），面板会尊重你写的那个值，不会覆盖。

## 5. 实例图标也认 `world/` 下的文件

以前只读实例根目录的 `server-icon.png` / `icon.png`。
现在 `world/server-icon.png`、`world/icon.png` 也能认（**优先级最低**：
根目录里放了正确的那个，永远以根目录为准）。

## 6. 日志分析的平台切换修好了

以前在「日志分析」页把平台从「自动」改成 `mclo.gs`（或 `LogShare`），点了分析之后
**仍然走 LogShare** —— 选择被忽略了。

原因是内置平台没有数据库记录，它们和「自动」在下拉里的值都是 `0`，浏览器把它们当成同一个值。
现在下拉用「类型 + 记录号」的组合值区分，并且**指定了平台就不会自动回退**：
该平台不可用时直接告诉你原因，而不是悄悄换一家、把你的日志发到你没选择的地方去。

## 7. LogShare 的排队与限流说明

LogShare 是**免费公益服务**，高峰期它的 AI 分析队列会满，此时接口会返回
"AI 分析队列已满，请稍后重试"。这是**对方侧的限流**，与面板无关，
而上传日志、生成分享链接这些功能一直正常。

现在界面会：

- 显示排队状态（"已进入 LogShare 的分析队列，前面还有 N 个任务"）；
- 队列满时明确说明是对方限流，并给出两个按钮：**重试分析** 与
  **改用 mclo.gs 生成分享链接**；
- 失败的那条记录会留在「分析记录」里，**点开它就会重新分析**（不会重复上传日志）。

---

## 升级提示

- 覆盖二进制即可，**不需要改动配置**，数据库会自动迁移。
- 如果你部署过节点，建议**同时升级面板与节点**到同一版本（本项目不保证跨版本混用）。
- 已经上传到第三方的日志不受影响；面板侧的分析记录与删除凭据都保留。
