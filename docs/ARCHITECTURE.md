## 1. 两个二进制

| 组件 | 位置 | 职责 |
|---|---|---|
| **面板（Panel）** | 管理机 | 唯一对外入口：Web 界面、HTTP API、数据库；**不直接跑游戏进程** |
| **守护进程（Daemon）** | 每台节点一个 | 管本机所有实例：启停、控制台、文件、备份、监控、容器 |

两者用 **gRPC over mTLS** 通信，面板是客户端、daemon 是服务端。

```
浏览器 ──HTTP(S)/WebSocket──> 面板 ──gRPC(mTLS)──> 节点A 的 daemon ──> 实例 1..N
                                    └──────────> 节点B 的 daemon ──> 实例 1..N
```

**为什么拆成两个进程**：面板只管编排，游戏进程必须在游戏机上跑；同时 daemon 以 root 运行（要建用户、绑端口、管容器），把它与对外暴露的面板分开，是安全边界。

## 2. 一次「打开控制台」发生了什么

```
浏览器 WS ?token=…&spam=…
   → 面板校验 JWT 与实例权限
   → 面板 → daemon：gRPC 双向流 Console()
   → daemon：AttachConsole（原子地取快照 + 订阅增量）
   → 实例的 stdout（或日志文件尾部）逐行回传
```

要点：

- **快照与订阅必须原子**：先订阅再取历史会重复，先取历史再订阅会丢行
- 行过滤（屏蔽无用行）在两端都有开关，参数随 `?spam=` 传给 daemon
- 颜色在 daemon 侧按级别打真彩色标记，浏览器按明暗主题重新着色

## 3. 实例的两种运行方式

| | 原生（native） | 容器（docker） |
|---|---|---|
| 进程 | 用专用系统用户跑 `java` | 容器内跑 `java` |
| 隔离 | 独立 uid + 目录权限 | 只读根、能力全丢、无特权、端口仅回环 |
| 依赖 | 节点装 JDK | 节点装 Docker；运行时镜像由面板下发 |
| 何时选 | 默认、轻量 | 想要更强隔离，或多实例共存 |

daemon 启动时探测容器能力，条目会在面板「节点管理」显示。

## 3.5 节点是怎么接入面板的

面板「节点管理」里只有一个「+ 登记节点」入口，点开后选方式：

| 方式 | 谁主动 | 面板要不要存 SSH 凭据 | 适用 |
|---|---|---|---|
| ① 一键部署远端节点（SSH）| 面板推 | **要**（明文入库，注意数据库安全）| 手上有 root 密码/私钥 |
| ② 凭证交换 · 面板发起 | 节点拉 | 不要 | 不想交出 SSH 凭据；面板签一次性 token（15 分钟）|
| ③ 凭证交换 · 节点发起 | 节点拉 | 不要 | 同上；节点自签请求（30 分钟），面板凭请求内签名验真 |
| ④ 本机探测接入 | 面板连回环 | 不要 | 面板与 daemon 同机 |
| ⑤ 本机一键部署 | 面板本地装 | 不要 | 面板与 daemon 同机，且只装了面板 |

凭证交换的共同点：**私钥始终留在节点**，面板只签 CSR；证书里带一个稳定的节点身份（改显示名不影响身份）。
撤销后节点下一次心跳就会被拒（最迟 10 秒），**不依赖面板能否连到节点**。

## 4. 出网（穿透）的三种线路

| 线路类型 | 通道 | 端口来源 |
|---|---|---|
| **自建 frps** | 自建 frp 服务端 | 面板从端口段里分配 |
| **第三方单隧道** | 服务商的 frps | 服务商分配（固定） |
| **公网直出** | 不走穿透，节点直接对外 | 实例的本地端口 |

第三方线路有个容易踩的点：服务商对**登录字段的位置**（`auth.token` 还是 `metadatas.token`）、**代理名**、**transport 参数**都有要求，少一样就登录失败或注册失败。所以面板的导入功能会把这些原样记住并在下发时还原 —— 这也是为什么**不要手改**导入进来的配置。

## 5. 数据存在哪

| 数据 | 位置 |
|---|---|
| 面板数据库（用户、实例、线路、审计） | `/opt/mcpanel/data/mcpanel.db`（SQLite，WAL；同目录另有 `-wal`/`-shm`）|
| 实例文件 | `/opt/mcpanel/instances/<实例ID>/` |
| daemon 状态（pid、隧道） | `/opt/mcpanel/state/` |
| frpc 配置与日志 | 每实例目录下的 `frp/`、`logs/` |

## 6. 故障排查顺序

1. **面板起没起来**：`systemctl status atlmcpanel-panel`
2. **节点在不在线**：面板「节点管理」；daemon 日志 `journalctl -u atlmcpanel-daemon`
3. **实例起没起来**：实例页状态 + `console.log` 尾部
4. **穿透通不通**：线路「自检」（TCP + 注册两层结论）

面板是唯一入口，所以**面板挂了不影响已运行实例**——daemon 与游戏进程照常跑，只是暂时无法管理。

## 7. 安全边界（部署时请确认）

- daemon 以 root 运行，但**只监听内网/回环**，面板通过 mTLS 连它
- 实例以**专用低权用户**运行，不能读写其它实例的目录
- 容器化实例：根文件系统只读、能力全丢、端口只发布到 `127.0.0.1`
- 面板开放端口必须先改默认口令，并尽量配 HTTPS
- 面板的 systemd 单元默认开启一组内核级沙箱（禁止提权、根文件系统只读、只允许写安装目录等）；
  daemon 的加固**刻意更宽松**——它要建系统用户、管容器，锁死会直接让建实例失败。
  每条的取舍写在 `deploy/systemd/*.service` 的注释里
- 面板支持**自定义安全入口**（`server.security_entry`）：启用后只在 `/<入口>/` 下提供服务，其余路径返回 404。
  它降低被批量扫描命中的概率，**不是鉴权替代品**
