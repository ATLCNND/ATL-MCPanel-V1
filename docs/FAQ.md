# 常见问题

> ## ℹ️ 当前版本
>
> 推荐使用 **`v1.0.0-preview`**（prerelease）：**Minecraft 实例**与**通用容器 / 通用控制台实例**都完整可用
> （含容器化隔离、备份、穿透、控制台）；**面板默认以独立低权用户 + systemd 沙箱运行**。
> **自动备份默认是增量的**：首份是完整基线，其后只打包自上一环以来变化的文件；
> 恢复时点任意一环都会自动还原整条链；界面里按「链」显示。
> 实例有三种类型（Minecraft / 通用 Docker 容器 / 通用控制台程序），能力由类型声明、
> 界面按能力出页签 —— 老实例默认就是 Minecraft，行为与以前一致。
>
> 这是**第一个 preview**：功能面已冻结，可以开始试用；但**跨机链路**（面板与节点不在同一台机器）
> 本版尚未验证，面板 HTTPS 默认自签，其余已知限制见 Release 说明。
>
> 0.12.x 已撤回，请勿使用：那条线上的多实例模板架构已由 0.11.3 的能力化重构取代，
> 且它引入了新的迁移版本号。除本 preview 外，0.11.x 是当前唯一在维护的线。

## 面板打不开 / 打开是空白页

- 先确认服务在跑：`systemctl status atlmcpanel-panel`
- 确认端口没被防火墙挡住（默认 8080）
- 如果是**自签 HTTPS 证书**：浏览器会拦一次，点「继续访问」即可；但**控制台的 WebSocket 会被浏览器拒绝**（表现为「控制台一直显示连接错误」而其它功能正常）—— 换成受信任证书即可解决

## 控制台一直显示「连接错误」

按这个顺序查：

1. 面板是不是自签 HTTPS？是的话换证书（见上）
2. 节点在「节点管理」里是不是「在线」
3. 实例是不是在运行；daemon 重启后实例会进入**接管态**（只读），重启一次实例即可恢复

## 复制按钮点了没反应

`navigator.clipboard` 只在 **HTTPS 或 localhost** 下可用。用 `http://IP:端口` 访问时，面板会退回到兼容实现（`execCommand`），仍然可以复制，只是个别浏览器可能受限：

- 长按/全选手动复制始终可用
- 彻底解决的办法是给面板配 HTTPS

## 线路自检失败，但端口是通的

自检分两层：**TCP 可达** 和 **frpc 注册**。常见组合：

| 现象 | 含义 | 怎么办 |
|---|---|---|
| TCP 失败 | 节点到服务商的网络不通 | 查服务商地址/端口、出口防火墙；换个节点试试 |
| TCP 通但注册失败 | 连上了但被服务端拒绝 | 看自检给出的**服务端原话**；第三方线路多半是 token 位置、代理名或 transport 参数不对 —— 重新导入服务商给的配置，别手改 |
| 一直没有结论 | frpc 起来了但服务端不响应 | 第三方服务商常要求特定的 `transport.tls.*`，导入配置会带上；也可能是到服务商的链路很慢 |

## 导入第三方配置后实例连不上

1. 确认线路类型是「第三方单隧道」
2. 到「线路分配」里**绑定**那条已导入的隧道（第三方线路不能自己填端口，端口是服务商分配的）
3. 点线路的「自检」，通过后再让玩家连

## 公网直出：开端口时提示「该节点不支持」

公网直出的地址就是**某台节点自己的公网 IP**。给别的节点上的实例选它，玩家会连到另一台机器。

- 先到「节点管理」把该节点的**公网 IP** 填对
- 再选**这条节点自己**的那条直连线路

## 升级后会怎样

- 面板与 daemon 升级后，运行中的实例会进入**接管态**（控制台只读），**重启实例即可恢复**
- 数据库迁移是自动的，升级前建议备份 `/opt/mcpanel`（安装脚本也会自动备份）

## 数据放在哪 / 怎么备份

- 实例文件：`/opt/mcpanel/instances/<实例ID>/`
- 面板数据库：`/opt/mcpanel/data/mcpanel.db`（升级脚本会自动备份整个 `/opt/mcpanel`）
- 备份建议：直接对整个 `/opt/mcpanel` 做快照，或使用实例页的备份功能

## 自动备份怎么突然变小了？能恢复到某一天吗？

这是**增量备份**，属预期行为：

- 第一份自动备份是**完整基线**（和以前一样大），之后每份只装**自上一环以来变化的文件** ——
  所以常见情况是「第一份 5 GB，之后每份几 MB」
- 想恢复到某个时间点：直接在备份列表里点**那一条**即可。点增量也会**自动把整条链还原**
  （基线 → 各层增量 → 删除记录），得到的是一份完整目录，不是半成品
- 手动备份**永远是完整的**，不依赖任何链 —— 出事时的最后一道保险就是它
- 界面里按「链」显示：一条链一行，展开能看到每一环。想删中间某一环时界面会提醒
  「它之后的几环将无法恢复」，因为**链断了就不能再往后恢复**
- 保留策略按链淘汰（要么整条留、要么整条删），不会留下恢复不了的半条链；
  一条 6 环的链只占 1 个名额，不会把「保留 4 份」的额度吃光

## 支持哪些服务端

面板只负责**进程与文件**，不绑定具体核心：Paper / Purpur / Fabric / Forge / NeoForge / 原版服务端都可以，只要能用 `java -jar` 跑起来。

## 能不能不以 root 跑面板

可以，0.11.3 起是默认行为。安装脚本会建一个专用系统用户（默认 `atlpanel`），
并把它放进 systemd 沙箱：只可写 `data/` 与 `certs/`，`/etc`、`/usr`、`$HOME` 全部只读，
`PrivateTmp` / `PrivateDevices` / `RestrictAddressFamilies` / `SystemCallFilter` 全开。
想容器化运行也有随包的 `deploy/docker/`（`read_only` + `cap_drop: ALL` + 固定 UID）。

代价只有一个：**非 root 下不能用「在本机一键部署节点」**（那要写 `/etc/systemd/system`）。
在两台机器上分别装面板和节点时没有任何影响；确实需要一键部署时用
`PANEL_USER=root deploy/install.sh panel` 退回旧行为。节点 daemon 仍然是 root ——
它要跑实例、设 cgroup、建实例用户。

## 我想让它跑 Minecraft 以外的服务

0.11.3 起可以直接建**通用 Docker 容器**实例（填镜像、容器内端口、启动命令、环境变量、卷挂载）
或**通用控制台程序**实例（把二进制放进实例目录、写个 `start.sh`）。这两类实例没有
玩家 / 世界 / 日志分析 / 游戏设置这些 Minecraft 专属页签，只有控制台 / 文件 / 备份 / 日志。

节点上装好 Docker 后，daemon 会自动启用容器化能力（面板「节点管理」里能看到能力状态）。
容器化实例的根文件系统只读、能力全部丢弃、端口只发布到回环，隔离更彻底。
